## Objective

Prove that headless Chromium (as launched by `@wppconnect-team/wppconnect`'s bundled Puppeteer) can start and stay connected inside this project's Docker image, and update the `Dockerfile` with whatever system packages are required. This is a prerequisite spike — no plugin code is written in this task.

## Context

The project's `Dockerfile` (repo root) builds on `node:24-slim`, a minimal Debian base with no browser-rendering libraries installed (see the `runner` stage, lines 15-26 — only `openssl` is installed). Puppeteer's bundled Chromium requires a specific set of shared libraries (`libnss3`, `libatk1.0-0`, `libatk-bridge2.0-0`, `libcups2`, `libxcomposite1`, `libxdamage1`, `libxrandr2`, `libgbm1`, `libxkbcommon0`, `libasound2`, `fonts-liberation`, etc.) to launch successfully — the exact list depends on the Chromium version Puppeteer bundles, which depends on the `@wppconnect-team/wppconnect` version resolved by `yarn add`. Per the global convention (never pin a package version from memory), look up the current version before installing.

Production today runs on Heroku (`docs/kb/features/deploy-heroku.md`), which is explicitly **out of scope** for this task — focus only on the `Dockerfile` / Fly.io path (per `.plans/ecomanda-flyio`).

## Implementation Steps

### Step 1: Look up and add the dependency

Run `npm show @wppconnect-team/wppconnect version` to get the current latest version. Add it with `yarn add @wppconnect-team/wppconnect@<version>` — do not hand-pin a version from memory/training data.

### Step 2: Add Chromium system libraries to the Docker `runner` stage

Extend the `apt-get install` line in the `runner` stage (`Dockerfile` line 18) to include the packages Puppeteer's own troubleshooting docs list for Debian-slim bases. Keep the existing `openssl` install; add to the same `RUN apt-get update -y && apt-get install -y ...` line rather than a second layer, to match the existing single-layer convention.

### Step 3: Build and smoke-test Chromium launch

Build the image locally (`docker build -t atendio-wppconnect-spike .`) and run a throwaway script inside a container that calls `wppconnect.create()` (or the lower-level Puppeteer launch it wraps) with `headless: true` and the container-appropriate launch args (commonly `--no-sandbox`, `--disable-setuid-sandbox` are required inside Docker). Confirm the browser process starts without crashing and can reach `web.whatsapp.com` (network egress permitting in your test environment).

### Step 4: Record findings

If Chromium cannot be made to launch reliably within a reasonable memory budget, stop and flag this against the plan's Kill Criteria rather than proceeding to task-02.
